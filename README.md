# Automated Fault Detection for Distributed Checkpointing

## 1. About the Project

This repository implements a multi-process validation harness designed to catch subtle, silent checkpoint-resume bugs in distributed training pipelines (e.g., PyTorch DistributedDataParallel). It provides a formal **State Contract Registry** to explicitly define and validate the invariants of model, optimizer, scheduler, dataloader, EMA, and RNG states across all processes before training resumes.

> **Scope**: This is a research-engineering system for studying checkpoint consistency. It is not a general-purpose distributed-training platform.

## 2. Scenario and Background

A typical training pipeline maintains distributed state across multiple ranks, such as model weights, optimizer momentum, learning rate schedulers, and often an exponential-moving-average (EMA) "teacher" copy of a student model. In large-scale distributed setups, training is routinely interrupted and resumed from checkpoints. 

Ideally, the restored state should exactly match the uninterrupted state across all ranks. However, seemingly innocuous implementation details—such as relying on a scalar variable inside a distributed process—can lead to state drift between ranks if the data isn't synchronized correctly upon restoration.

## 3. About the Bug

Distributed models often resume training smoothly from checkpoints but silently suffer from state desynchronization across ranks. For instance:

- **EMA Scalar Omission**: A scalar `step` tracker used to calculate EMA decay rate is stored as a plain Python `int` rather than a registered tensor buffer. Upon restoration, only rank 0 successfully re-applies the scalar, leaving all other ranks with a stale value.
- **Data Cursor Mismatches**: Dataloaders increment out of sync when the `global_step` is improperly restored, causing ranks to process completely different global batches.
- **RNG Desynchronization**: Random number generator seeds diverge because the global RNG state is not properly synchronized across the distributed cluster.
- **Scheduler Stale State**: The learning rate scheduler's internal step counter is not restored correctly on non-zero ranks, leading to different learning rates across the cluster.
- **Optimizer State Corruption**: Optimizer momentum buffers or learning rate parameters are corrupted or omitted during restore on a subset of ranks.

These bugs are virtually invisible in single-rank loss curves, but cause the distributed shards to silently drift apart. Over time, this leads to diverging model weights, degraded accuracy, or sudden training instability that is notoriously difficult to debug.

## 4. What Has Been Experimentally Validated

**End-to-End Resume Fidelity** (Deterministic Configuration)

When a checkpoint is saved and resumed without faults under a deterministic seed configuration, the resumed training states exactly matched the uninterrupted reference trajectory across all tested workloads:

| Experiment | Baseline Loss | Resumed Loss | Exact Match? |
|------------|---------------|--------------|--------------|
| resnet_smoke | 2.798869 | 2.798869 | Yes |
| small_transformer_smoke | 10.620230 | 10.620230 | Yes |

> These results were obtained under tested deterministic configurations (fixed seeds, `gloo` backend, 2 ranks, CPU). Results may differ under non-deterministic conditions (e.g., CUDA, NCCL, larger world sizes).

## 5. Architecture

### Validation Protocol

The validator uses a two-stage protocol to minimize overhead:

1. **Digest phase**: Each rank computes a SHA-256 digest of its local state.
2. **Gather phase**: Digests are gathered and compared. Full state is only gathered if a mismatch is detected.

### State Contract Scopes

| Scope | Meaning | Validation Rule |
|-------|---------|-----------------|
| GLOBAL | One logical value across all ranks | Consensus / equality |
| REPLICATED | Equivalent copy on every rank | Digest / equality |
| PER_RANK | Intentionally rank-specific | Rank-specific reference |
| SHARDED | Partitioned logical state | Coverage + consistency |
| LOCAL | Process-local, not validated | No cross-rank equality |

### Supported Comparators

| Comparator | Semantics |
|------------|-----------|
| EXACT | Strict equality (`==`) |
| ALLCLOSE | Floating-point tolerance (`rtol`, `atol`) |
| HASH | SHA-256 digest equality |

> `NORM` and `CUSTOM` comparators are reserved but not implemented. Using them will raise `UnsupportedComparatorError` at contract registration time.

## 7. Setup and Usage

The project utilizes `uv` for Python dependency management.

```bash
uv sync
```

### Run the Fault Injection Matrix
Runs the baseline for all workloads, mutates checkpoints with simulated bugs, and validates restoration:
```bash
./scripts/run_fault_matrix.sh
```

### Measure Validation Overhead
Runs workloads with validation disabled then enabled, computing wall-clock overhead with multiple repetitions:
```bash
./scripts/run_benchmarks.sh [repetitions]
```

### Run Scalability Tests
Measures validation overhead across different world sizes:
```bash
./scripts/run_scalability.sh [repetitions]
```

### Generate Evaluation Tables
Parses raw JSON results and generates Markdown tables (A–E):
```bash
./scripts/generate_paper_tables.sh
```

### Run Unit Tests
```bash
uv run python -m pytest tests/ -v
```

## 8. Experiment Result Schema

Every experiment run emits a machine-readable JSON record (`raw_results.json`) with:
- Experiment identity (id, workload, fault, phase)
- Configuration (world_size, backend, device, seed)
- Validation results (detected states, root cause, causal attribution)
- Timing (training_duration_s, validation_duration_ms, checkpoint_duration_s)
- Reproducibility (git_sha, config_hash, environment metadata)

Results are written to: `results/raw/<experiment_id>/<run_id>/raw_results.json`

## 9. Limitations

The following limitations should be considered when interpreting results:

- **Backends**: Only `gloo` backend has been extensively tested. `nccl` support exists but is less validated.
- **World sizes**: Tested with 1, 2, and 4 ranks. Larger world sizes have not been validated.
- **Workloads**: Tested with TinyTransformer, ResNet-18 (CIFAR-10), and SmallTransformer. Results may not generalize to all model architectures.
- **Sharded state**: `ShardDescriptor` and sharded validation are implemented but no workload currently exercises sharded checkpointing. Validation is structural (shape/coverage/overlap) rather than semantic.
- **Determinism**: Resume equivalence results hold under strict deterministic seeding. CUDA non-determinism, `cudnn.benchmark`, or non-deterministic operations can cause legitimate divergence that would be flagged.
- **Data loader**: The data cursor contract relies on `global_step` as a proxy. It does not capture the full sampler/iterator state for complex data pipelines.
- **Fault model**: Only offline fault injection (mutating checkpoint payloads) is tested. Runtime faults (e.g., bit-flips during forward pass) are not modeled.
- **Overhead measurement**: Benchmark timing excludes setup/download time but includes Python-level overhead. Results are representative for the tested configurations.
- **Unsupported comparators**: `NORM` and `CUSTOM` comparators are not implemented. Workloads that previously used `CUSTOM` have been migrated to `ALLCLOSE` (for optimizer) and `EXACT` (for scheduler).
- **Hardware**: Tested on CPU. GPU-specific behaviors (memory layout, tensor core non-determinism) may introduce differences not captured by current contracts.
- **State consistency vs semantic equivalence**: The validator checks state consistency (do all ranks agree?) — it does not verify that the training semantics are correct.
